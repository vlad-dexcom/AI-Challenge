# День 29 — оптимизация локальной LLM под задачу

Задача: RAG-ассистент по фитнес-базе знаний (английский корпус, вопросы на EN и RU): ответ с проверяемыми цитатами, честное «не знаю» вне корпуса, ответ на языке вопроса, интерактивная скорость на Apple M3 Pro 36 ГБ.
Оптимизировались: параметры (temperature, max tokens, context window), квантование, prompt-шаблон. Результат: модель `gemma4:26b-a4b-it-qat` с профилем промптов `local` и настройками по умолчанию (`OllamaTuning.RECOMMENDED`), упакованная в `rag/local-model/Modelfile`.

## Методика
- Два набора вопросов. **tuning** — 16 вопросов дня 28 (подбор). **hold-out** — 28 новых вопросов (`rag/eval/local-rag/holdout.json`: 13 specific, 7 common, 4 *partial* — вопрос из двух частей, корпус отвечает только на первую, 4 вне корпуса; 8 русских), на которых ничего не подбиралось. Примеры в промптах взяты из тем, которых нет ни в одном наборе.
- Одинаковые настройки конвейера (filter + rerank + rewrite, topK 4/10, порог 0.65, цитаты), каждая конфигурация — на свежем сервере, модели выгружаются между конфигурациями. Повторы: 3 (база и итог fast), 2 (остальные).
- Метрики считаются кодом: факты (`mustContain`), «не знаю» по корпусу (IDK in), отказ вне корпуса (OOC), частичные вопросы (факты поддержанной части), верифицированные цитаты, язык ответа, задержка (медиана/p90), память (`ollama ps`), холодный старт. Профиль вызовов — токены и тайминги по назначению вызова (`GET /api/llm/stats`).
- Оговорки: «факты» ищут точные фразы, поэтому на hold-out метрика консервативна (верный ответ своими словами не засчитывается) — сравниваются конфигурации между собой, а выводы опираются на «не знаю по корпусу» и частичные вопросы. Холодный старт сильно колеблется (2,7–12 с у одной и той же модели) из-за кэша диска — как ориентир, не как сравнение. Скрипты и сырые ответы: `rag/eval/local-rag/` (`optimize.py`, `optimize_report.py`, `session_profile.py`, `optimization/*.json`).

## Профиль вызовов (что именно считает модель)
| Вызов | Промпт, токены (среднее / макс) | Ответ, токены (среднее / макс) | Скорость генерации |
|---|---|---|---|
| ответ с цитатами (одиночный) | 1170 / 1660 | 250 / 490 | fast 40 tok/s, smart 17 tok/s |
| rewrite запроса | 115 / 126 | 15 / 24 | — |
| чат с памятью: ответ | 1840 / 2100 | 425 / 680 | 38 tok/s (fast) |
| чат с памятью: извлечение памяти / rewrite / сводка | 750 / 780; 660 / 820; 380 / 470 | 62; 10; 184 | — |

Prefill у fast ≈ 600 tok/s, у smart (MLX) ≈ 108 tok/s: примерно 11 из 25 секунд ответа smart — чтение 1,2K-токенного промпта, большую часть которого занимают 4 чанка контекста.

## 1. Параметры
| Конфигурация (fast, базовые промпты) | Память | Медиана | Качество tuning / hold-out |
|---|---|---|---|
| `num_ctx` 16K (было) | 15,7 ГБ | 7,4 с | 85% / 78% |
| `num_ctx` 4K | 15,4 ГБ | 7,4 с | 85% / 81% |
| 4K + лимиты токенов (rewrite 64, ответ 700) | 15,4 ГБ | 7,6 с | 85% / 81% |
| smart, `num_ctx` 4K | 28,5 ГБ (как при 16K) | 25,5 с (было 26,4) | без изменений |

- Размер контекста **не влияет на память и скорость**: у Gemma 4 скользящее окно внимания, KV-кэш мал; гипотеза «16K съедает память» не подтвердилась. Промпты не превышают 2,1K токенов (в чате с памятью), поэтому выбран **8K** с запасом.
- Лимиты токенов скорость не меняют (ответы короче лимита), но защищают от зацикливания: rewrite — одна короткая строка (64), ответ с цитатами — 1024 (в чате пик 680).
- Температура уже 0 у всех этапов, кроме обычного ответа без цитат (0.2), поэтому резерва нет. Серверные `flash attention` и KV-кэш `q8_0` в сервисе Ollama уже включены.
- Находка по надёжности: при температуре 0 модель иногда зацикливается и Ollama отвечает HTTP 500 `token repeat limit reached`; одинаковый повтор зациклится снова. `OllamaTextGenerator` теперь повторяет такой вызов один раз с `temperature 0.3` и `repeat_penalty 1.1`.

## 2. Квантование (`gemma4`, базовые промпты, 2 повтора)
| Вариант | Память | Медиана | Hold-out: факты / частичные | Комментарий |
|---|---|---|---|---|
| **26B-A4B `it-qat`** (GGUF, выбран) | **15,7 ГБ** | **7,5 с** | 78% / 33% | базовая линия |
| 26B nvfp4 (MLX) | 25,4 ГБ | 6,9–8,4 с | 80% / 25% | качество то же, памяти на 10 ГБ больше |
| 26B `q4_K_M` (GGUF) | 18,0 ГБ | 9,5 с | 76% / 0% | медленнее, холодный старт 28 с |
| 12B `it-qat` (GGUF) | 8,2 ГБ | 35–48 с | 84% / 62% | неприемлемо медленно |
| 12B nvfp4 (MLX) | 16,8 ГБ | 11–15 с | 90% / 100% | качество выше базы, но вдвое медленнее fast |
| 31B nvfp4 (MLX, smart) | 28,5 ГБ | 26–27 с | 76% / 0% | см. итог smart |

QAT остаётся лучшим по памяти, скорости и качеству вместе; MLX-сборки занимают заметно больше памяти (по `ollama ps`), MoE-26B быстрее плотных 12B/31B. Различия в качестве между квантованиями на этих наборах — на уровне шума, кроме скорости и памяти.

## 3. Prompt-шаблон (`PromptProfile`)
Профиль `local` (облачный путь использует исходные промпты — побайтово, есть тест) состоит из четырёх независимых рычагов, измерены по отдельности (fast, 2 повтора):

| Рычаг | Tuning факты / «не знаю» | Hold-out факты / «не знаю» | Частичные |
|---|---|---|---|
| (ничего, база; 3 повтора) | 85% / 15% | 78% / 11% | 33% |
| `partial`: отвечать на подтверждённую часть вопроса и сказать, чего не хватает | 97% / 0% | 86% / 0% | 79% |
| `rewrite`: rewrite запроса с примерами; сохранять термины вопроса, не выдумывать названия | 100% / 0% | 76% / 13% (2 ошибки зацикливания) | 42% |
| `lang`: явная подсказка языка для русских вопросов | 92% / 8% | 79% / 10% | 38% |
| `compact`: короткий JSON-контракт | 92% / 8% | 80% / 8% | 75% |
| **все четыре (`local`)** | **100% / 0%** | **83% / 4%** | **88%** |

- Главный рычаг — `partial`: «не знаю» на вопросах по корпусу исчезает, частичные вопросы 33% → 79%, отказ вне корпуса остаётся 100%.
- `rewrite` лечит провал rewrite (c07, ru-c08 у Local-fast); облачная модель когда-то выдумала «RAMP protocol» на вопросе про разминку — теперь это запрещено правилом промпта.
- `compact` почти не уменьшает промпт (1172 → 1160 токенов): контекст чанков занимает большую часть; польза лишь в сочетании с остальными.
- Rewrite-промпт стал на ~90 токенов длиннее (115 → 203): +35 мс у fast, +0,3 с у smart (медленный prefill).

**Local-fast** (`gemma4:26b-a4b-it-qat`, итоговая конфигурация: профиль `local`, `num_ctx` 8K, лимиты токенов; 3 повтора, 132 ответа):

| Метрика | До | После |
|---|---|---|
| Факты, tuning / hold-out | 85% / 78% | **100% / 83%** |
| «Не знаю» по корпусу, tuning / hold-out | 15% / 11% | **0% / 4%** |
| Частичные вопросы | 33% | **88%** |
| Отказ вне корпуса | 100% | 100% |
| Верифицированные цитаты, tuning / hold-out | 85% / 85% | **92% / 96%** |
| Язык ответа, tuning / hold-out | 94% / 96% | 100% / 93%* |
| Медиана / p90, tuning | 7,4 / 11,2 с | 8,1 / 10,9 с |
| Медиана / p90, hold-out | 7,5 / 13,3 с | 7,6 / 13,4 с |
| Память (`ollama ps`) | 15,7 ГБ | 15,6 ГБ |
| Повторы совпали (решение и покрытие фактов) | 43 из 44 вопросов | 44 из 44 |
| Ошибки | 0 | 0 |

\* Два «провала языка» на hold-out — не вина модели. h27 (`Кто выиграл CrossFit Games 2024?`) — детектор языка считал буквы, и английский термин перевешивал русское «Кто выиграл», поэтому отказ формировался по-английски (было так и до оптимизации, 3/3). Исправлено: язык определяется по словам (`IdkResponder.detectLanguage`, тест). h17 — русский ответ с английскими цитатами в кавычках, метрика языка считает долю кириллицы.

**Регрессии у Local-fast** (честно): на hold-out один вопрос стал хуже — h07 («что именно в тренировке B домашней недели», факты 100% → 0%, модель теперь отвечает «не знаю» во всех 3 повторах: новый rewrite запросил менее удачные слова) и частично h06 (факты 100% → 67%). Выигрыши (c07, ru-c08, h22–h24, h09) заметно перевешивают, но rewrite остаётся самым хрупким местом.

**Local-smart** (`gemma4:31b-mlx`, профиль `local`, 2 повтора):

| Метрика | До | После |
|---|---|---|
| Факты, tuning / hold-out | 100% / 76% | 100% / **91%** |
| «Не знаю» по корпусу, hold-out | 17% | **0%** |
| Частичные вопросы | 0% | **88%** |
| Цитаты, hold-out | 83% | **100%** |
| Медиана / p90, hold-out | 27,0 / 34,3 с | 29,4 / 36,9 с (ответы длиннее: 290 против 233 токенов) |
| Память | 28,5 ГБ | 28,1 ГБ |

100% у smart на tuning-наборе на hold-out не воспроизвелись (76%): на новых вопросах smart отказывался отвечать на частично покрытые вопросы — профиль `local` это исправил.

## Выводы
- Основной выигрыш дали **промпты**, а не параметры: «не знаю» по корпусу 11–17% → 0–4%, частичные вопросы 0–33% → 88%, цитаты 83–85% → 96–100%, цена — +0–2 с и ответы на 20% длиннее.
- Параметры и квантование: контекст не влияет, лимиты токенов — страховка, QAT остаётся лучшим выбором; ради скорости ничего менять не нужно, ради памяти — только QAT.
- Для интерактива — fast (7,6 с, 15,6 ГБ), для ответа без компромиссов по качеству — smart (29 с, 28 ГБ). Ускорить smart можно только сокращением контекста (топ-3 чанка, чанки короче) — не проверялось.
- Не сделано: ускорение prefill у smart, оценка эксперта вместо проверки по ключевым фразам, Modelfile с `TEMPLATE` (шаблон чата модели не менялся).

## Окно сравнения «до / после» в веб-интерфейсе (для видео)
`./gradlew :web-console:run` → вкладка Chat → **Answer with → Compare: before vs after optimization (Day 29)**. Панель сверху: таблица «что изменили» (значения берутся из реальных настроек сервера, изменённые строки подсвечены), итоги бенчмарка до/после (fast и smart, наборы hold-out и tuning), кнопки демо-вопросов (c07, ru-c08, h22–h24, вне корпуса c09 и регрессия h07).
Вопрос последовательно отправляется в «до» (`provider=ollama-baseline`: исходные промпты, параметры по умолчанию) и «после» (`provider=ollama`: профиль `local` + рекомендованные настройки) — одна и та же модель; под колонками строка сравнения (ответ / «не знаю», задержка, вызовы LLM, проверенные цитаты, длина ответа). Числа бенчмарка лежат в `web-console/src/main/resources/ui/optimization-summary.json` и пересоздаются `python3 rag/eval/local-rag/make_summary.py`.

## Что в коде
- `OllamaTuning` / `OllamaParams` (temperature, top_p/top_k, repeat_penalty, `num_ctx`, `num_predict`, keep_alive; глобально или по назначению вызова `CallPurpose`), `OllamaTuning.RECOMMENDED`, `--ollama-tuning` / `OLLAMA_TUNING` (`none` — без переопределений). `LlmCallStats` и `GET /api/llm/stats` — токены и тайминги по назначению.
- `PromptProfile` (`rewrite`, `partial`, `lang`, `compact`; `local` — все), `--prompt-profile` / `RAG_PROMPT_PROFILE`; для Ollama по умолчанию `local`, для Gemini всегда исходные промпты.
- `rag/local-model/Modelfile` → `ollama create trainer-rag-fast -f rag/local-model/Modelfile` (`num_ctx 8192`, `temperature 0.3`, system-промпт тренера) для клиентов, которые ходят в Ollama напрямую (curl, приватный шлюз дня 30).
- Откат при зацикливании (`token repeat limit`), исправление определения языка отказа.
