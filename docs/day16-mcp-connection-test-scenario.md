# Сценарий проверки подключения MCP (Day 16)

Ручной сквозной сценарий для проверки подключения к MCP-серверу и получения списка доступных
инструментов — как в интерфейсе приложения, так и в Logcat.

---

## Подготовка

1. Соберите и установите отладочную сборку на эмулятор или устройство:
   ```bash
   ./gradlew :app:installDebug
   ```
2. Откройте Logcat с фильтром по тегу `MCP`:
   ```bash
   adb logcat -s MCP
   ```
3. Откройте приложение — попадаете в обычный экран чата.

---

## Шаг 1 — Открытие экрана MCP

1. В верхней панели чата нажмите новую иконку 🔧 (гаечный ключ/сборка).

**Ожидаемый результат:**
- Открывается экран «MCP» с полем ввода URL сервера, предзаполненным значением
  `https://mcp.deepwiki.com/mcp`, и кнопкой «Подключиться».
- Список инструментов пуст, статус — «Не подключено».

---

## Шаг 2 — Установка соединения (happy path)

1. Оставьте URL по умолчанию (`https://mcp.deepwiki.com/mcp`) и нажмите «Подключиться».

**Ожидаемый результат:**
- Кратко отображается статус «Подключение…».
- После успешного ответа сервера экран показывает карточку с информацией о сервере (имя,
  версия) и список из **трёх** инструментов: `read_wiki_structure`, `read_wiki_contents`,
  `ask_question`, у каждого — описание и параметры (где применимо).
- Кнопка «Подключиться» меняется на «Переподключиться» / «Отключиться».
- В Logcat (тег `MCP`) видно:
  - запись об успешном подключении с именем/версией сервера;
  - запись о полученном списке инструментов (3 шт.) с их именами.

---

## Шаг 3 — Отключение и повторное подключение

1. Нажмите «Отключиться».
   - Статус возвращается к «Не подключено», список инструментов очищается.
   - В Logcat — запись об отключении.
2. Нажмите «Подключиться» снова.
   - Соединение и список инструментов восстанавливаются так же, как в Шаге 2.

---

## Шаг 4 — Некорректный URL / нет соединения

1. Замените URL на заведомо нерабочий, например `https://mcp.invalid.example/mcp`, и нажмите
   «Подключиться».

**Ожидаемый результат:**
- Через несколько секунд отображается баннер ошибки с понятным сообщением (например, «Не удалось
  подключиться к MCP-серверу…»), список инструментов остаётся пустым.
- В Logcat — запись об ошибке подключения (уровень `Error`), с той же информацией.
- Приложение не падает; можно исправить URL и повторить попытку.

---

## Шаг 5 — Пустой URL

1. Очистите поле URL полностью и нажмите «Подключиться».

**Ожидаемый результат:**
- Подключение не выполняется; отображается сообщение о необходимости указать URL сервера.
- Сетевой запрос не отправляется (в Logcat нет записи о попытке подключения к пустому адресу).

---

## Шаг 6 — Существующий функционал не сломан

1. Вернитесь на экран чата (кнопка «назад»).
2. Отправьте обычное сообщение в чат (например, «Привет, как дела?»).

**Ожидаемый результат:**
- Чат с Gemini продолжает работать как прежде: ответ приходит, токены в плашке под ответом
  отображаются корректно — обновление тулчейна (Kotlin 2.4.0 / Ktor 3.5.1) не повлияло на
  основной функционал приложения.

---

## Итог

| Критерий приёмки | Проверено |
|---|---|
| Соединение с MCP-сервером устанавливается | Шаг 2 |
| Список инструментов корректно возвращается (в UI и в Logcat) | Шаг 2 |
| Ошибки подключения обрабатываются корректно, без падения приложения | Шаг 4, Шаг 5 |
| Повторное подключение/отключение работает | Шаг 3 |
| Существующий функционал (чат с Gemini) не сломан | Шаг 6 |
