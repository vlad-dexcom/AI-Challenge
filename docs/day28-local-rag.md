# День 28 — локальная LLM + RAG (retrieval и генерация полностью локально)

Цель: подключить локальную модель к RAG-конвейеру на индексе корпуса, выполнять retrieval локально, генерировать ответ локальной моделью, сравнить с облаком
(качество, скорость, стабильность). Результат: RAG-система, полностью работающая локально (Ollama, без ключа и интернета).

## Что сделано

## Выбор локального эмбеддера
Готовый eval-набор мал (26 EN + 14 RU вопросов), различия тонули в шуме. Поэтому дополнительно сгенерирован набор из 213 вопросов (по одному на чанк, EN + RU,
генерировала `gemma4:26b-a4b-it-qat`), ground truth — конкретный чанк (`rag/eval/local-rag/embedder-selection/`).

| Эмбеддер | EN hit@1 / hit@5 / MRR | RU hit@1 / hit@5 / MRR | файл-источник hit@1 EN / RU |
|---|---|---|---|
| Gemini `gemini-embedding-001` (облако) | 68,5 / 94,8 / 0,790 | 63,4 / 93,4 / 0,749 | 94,8 / 92,0 |
| **`embeddinggemma-2:270m-bf16-text` + prompts** | **59,2 / 88,7 / 0,708** | **56,8 / 85,9 / 0,679** | 91,5 / 87,8 |
| `embeddinggemma-2:270m` (nvfp4) + prompts | 57,3 / 86,9 / 0,691 | 53,1 / 83,1 / 0,649 | 90,1 / 85,9 |
| `bge-m3` | 56,3 / 83,6 / 0,666 | 50,2 / 75,6 / 0,601 | 89,2 / 81,7 |
| `qwen3-embedding:0.6b` | 55,4 / 86,4 / 0,678 | 41,8 / 77,9 / 0,557 | 88,3 / 75,6 |

- bf16 лучше nvfp4 на 1,5–3,7 п.п.; префиксы задач помогают (особенно hit@5). `embeddinggemma-2:740m-bf16` дал идентичные цифры (та же текстовая башня), поэтому взята 270m (574 МБ).
- `qwen3-embedding` на русских вопросах к английскому корпусу заметно слабее.
- Порог косинуса 0.65 подошёл и локальному эмбеддеру (`sweep`: 100% вопросов вне корпуса отсечено, 0% in-corpus отклонено), пересчитывать не пришлось.
- Оговорка: вопросы сгенерированы Gemma — возможен лёгкий перекос в пользу эмбеддера той же семьи; метрика по чанкам строгая (соседний чанк того же файла тоже был бы полезен).

## Полностью локальная работа (проверено)
CLI и веб-консоль запускались под `sandbox-exec` с запретом исходящей сети (всё, кроме localhost; `curl` к Gemini → `000`), `GEMINI_API_KEY` не задан:
- `ask` (EN и RU, filter + rerank + rewrite): русский вопрос переписан в английский поисковый запрос, найден чанк, ответ на русском, цитата проверена в источнике.
- Сессия с памятью задачи: Gemma сама извлекла цель и ограничения (`injury: bad knee`, `equipment: no gym`), второй ответ учёл контекст.

## Сравнение Cloud / Hybrid / Local
Стенд: Apple M3 Pro 36 ГБ, Ollama 0.40.1. Вопросы: 10 контрольных (`rag/eval/control-questions.json`, 8 по корпусу + 2 вне), 4 русских перевода контрольных, 2 русских (по корпусу и вне) = 16.
Настройки одинаковы: filter + rerank + rewrite, topK 4/10, порог 0.65, цитаты включены, индекс `structure`. 3 повтора каждой конфигурации (48 ответов), модель прогрета (холодный старт отдельно).
Скрипты и сырые ответы: `rag/eval/local-rag/` (`benchmark.py`, `report.py`, `results.json`).

| Конфигурация | Факты | «Не знаю» на вопросах по корпусу | «Не знаю» ровно где нужно | Цитаты верифицированы | Язык ответа | Медиана / p90 | Вызовов LLM | Холодный старт |
|---|---|---|---|---|---|---|---|---|
| **Cloud** (Gemini + Gemini) | 95% | 8% | 94% | 92% | 100% | 7,2 / 8,8 с | 1,9 | — |
| **Hybrid** (локальный retrieval + Gemini) | 97% | 5% | 96% | 95% | 100% | 7,5 / 8,4 с | 1,9 | — |
| **Local-fast** (`gemma4:26b-a4b-it-qat`) | 85% | 15% | 88% | 85% | 94% | 7,5 / 11,5 с | 2,1 | 6,3 с |
| **Local-smart** (`gemma4:31b-mlx`) | **100%** | **0%** | **100%** | **100%** | 100% | 26,5 / 32,3 с | 1,9 | 12,0 с |

«Факты» — доля обязательных фактов (`mustContain` контрольного набора) в ответе и цитатах; «не знаю ровно где нужно» — IDK на вопросах вне корпуса и ответ на остальные;
цитаты — все цитаты найдены дословно в чанках. Метрика «ожидаемый источник процитирован» (54–62%) строгая (файл + ключевое слово раздела) и здесь несравнимо шумная, в выводах не используется.

**Качество.** Local-smart безошибочен на этом наборе, Local-fast слабее облака на 10 п.п. по фактам. Все конфигурации одинаково и правильно отказываются на вопросах вне корпуса (c09, c10, ru02: «не знаю» 3/3) — без галлюцинаций.
Провалы по корпусу: Local-fast — c07 (белок) и ru-c08 (становая, русский вопрос); Cloud — c05 (разминка), Hybrid — c05 в 2 из 3 повторов. Проверено отдельно:
c07 у Local-fast с **выключенным** rewrite проходит, с включённым — нет, а Gemini с тем же retrieval отвечает. То есть узкое место — **LLM-переписывание запроса** (слабый поисковый запрос → нужного чанка нет в топ-4 → модель честно отвечает «не знаю»),
а не локальный эмбеддер (Hybrid с локальным retrieval не хуже Cloud) и не стадия ответа. Local-fast также ответил по-английски на русский вопрос ru-c05 (3 из 3 повторов).

**Скорость.** Local-fast на прогретой модели сопоставим с облаком (медиана 7,5 против 7,2 с), но p90 хуже (11,5 против 8,8 с) и есть холодный старт (6 с; у 31b — 12 с). Local-smart в 3,7 раза медленнее облака (26,5 с): плотная 31B упирается в пропускную способность памяти (~17 tok/s против ~40 у MoE).
Число вызовов LLM на ответ одинаково (~2: rewrite + ответ).

**Стабильность.** Ошибок, таймаутов и 429 не было ни в одной конфигурации (по 48 запросов). Повторы почти идентичны: у Cloud, Local-fast и Local-smart решение (IDK/ответ) и покрытие фактов совпали на 16 из 16 вопросов во всех трёх прогонах,
у Hybrid — на 15 из 16 (c05 зависит от текста, который переписывает запрос). Без интернета система продолжает работать; облако зависит от сети и квот.

## Выводы
- Полностью локальная RAG-система работает без ключа и интернета и по цитатируемости и честности («не знаю») не уступает облаку.
- Для интерактивного чата — `gemma4:26b` (скорость как у облака, но слабее на переписывании запросов); для максимального качества и когда ответ может подождать — `gemma4:31b-mlx`.
- Слабое звено локального конвейера — rewrite. Практические варианты: выключать rewrite для английских вопросов (оставлять для русских), использовать большую модель только для rewrite, либо улучшить промпт переписывания. В этой работе не реализовано.
- Эмбеддер `embeddinggemma-2` достаточен: файл-источник находится в 88–92% случаев; разница с Gemini заметна только на строгих метриках по чанкам.

## Ограничения
16 вопросов, 3 повтора на конфигурацию — различия в 1–2 вопроса не значимы; «факты» — проверка по ключевым словам, а не оценка экспертом; ответы с цитатами, rewrite и память генерируются при temperature 0 (0.2 только у обычного ответа без цитат), поэтому совпадение повторов — во многом следствие нулевой температуры, а не доказательство стабильности модели;
замеры скорости — на незанятой машине; наборы вопросов и эмбеддер-выбор частично созданы той же Gemma, которую оценивают.

## Находки по ходу работы
- `gemma4:31b-mlx` (MLX-раннер) не поддерживает `format: "json"` (HTTP 501): первый прогон дал 45 ошибок из 48 → добавлен автоматический откат без `format` (с тестом).
- Модели Ollama с `embed` в имени скрываются из списка моделей чата.
- Имена моделей с `:` (`gemma4:26b-a4b-it-qat`) пришлось разрешить в проверке имени модели веб-консоли.

## Как запустить
```
ollama pull gemma4:26b-a4b-it-qat gemma4:31b-mlx embeddinggemma-2:270m-bf16-text   # нужна Ollama >= 0.40
./gradlew :rag:tools:run --args="index --provider ollama"                           # rag/index-local
./gradlew :rag:tools:run --args='ask "How much protein per kg?" --provider ollama --mode rag --filter on --rerank on --rewrite on'
./gradlew :web-console:run                                                          # Chat → Answer with: Local / Hybrid / Compare
```
