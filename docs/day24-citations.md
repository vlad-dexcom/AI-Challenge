# Day 24: цитаты, источники и защита от галлюцинаций (RAG)

Задание: RAG-ответ **обязан** содержать ответ, список источников (файл + раздел/`chunk_id`) и цитаты (фрагменты найденных чанков); при слабом
контексте ассистент говорит «не знаю» и просит уточнить. Реализовано в модуле `:rag` (`Citations.kt`, `RagPipeline`, `CitationsEval.kt`),
веб-чате (`ui`) и агенте `Knowledge Coach (RAG)` в приложении.

## Контракт ответа
Модель возвращает один JSON-объект (в `generateContent` — `responseMimeType=application/json` через `GenerationOptions(json=true)`, температура 0;
в приложении Interactions API не имеет поля JSON-режима в нашем `LlmClient`, поэтому там JSON запрашивается только промптом, а ответ разбирает
терпимый парсер: markdown-ограждения и текст вокруг `{...}` допустимы):

```json
{"answerable": true, "answer": "...", "sources": [{"file": "...", "section": "...", "chunkId": "..."}], "quotes": [{"chunkId": "...", "text": "..."}]}
```
- Каждый чанк в промпте подписан `chunkId` (стабильный id из индекса, `файл#structure-N`), `file`, `section`.
- **Цитаты остаются на языке корпуса (английском)**, даже если ответ русский: их нельзя переводить или перефразировать, иначе нельзя проверить
  кодом. Ответ пишется на языке вопроса.
- `answerable=false`, если чанки не содержат ответа (даже при близкой теме).

## Проверка цитат кодом (`CitationVerifier`, без LLM)
1. Цитата должна быть подстрокой чанка **после нормализации**: регистр, пробелы/переносы, типографские кавычки и тире, `ё`/`е`, markdown-символы
   (`* _ # > |`) и маркеры списков. Допускается `...`/`…` между фрагментами одного чанка (в том же порядке). Минимум 12 символов.
2. `VERIFIED` — найдена в указанном чанке; `REATTRIBUTED` — слово в слово есть в *другом* найденном чанке (id исправлен и отмечен);
   `NOT_FOUND` — выдумана/изменена; `TOO_SHORT`.
3. Источник валиден, если его `chunkId` (или единственное совпадение file+section) среди чанков, отданных модели. Невалидные источники не показываются.
4. Ответ принимается, если ≥1 валидный источник и ≥1 проверенная цитата. Иначе — **один повтор** со строгим промптом (с причиной отказа),
   затем «не знаю». Непарсящийся JSON — один ремонтный вызов, потом тот же повтор.
Невыявленные подделки (`NOT_FOUND`) остаются в ответе с пометкой ⚠ и попадают в отчёт верификации.

## Режим «не знаю» (`IdkResponder`)
Срабатывает: (а) ни один чанк не прошёл порог Day 23 (LLM не вызывается); (б) модель вернула `answerable=false` (случай c10: cosine 0.731 выше порога,
но бренда в базе нет); (в) проверка не прошла после повтора (`VERIFICATION_FAILED`/`MALFORMED_OUTPUT`).
Ответ — **на языке вопроса** («Не знаю: …» / «I don't know: …»), один уточняющий вопрос и «ближайшие темы (это не ответ)».
Это заменяет английскую заглушку Day 23 (она остаётся только при выключенных цитатах: `citations=false`).

**Уточняющий вопрос — шаблон, а не LLM-вызов.** Причины: ноль доп. стоимости/латентности, нет шанса на свободные утверждения в «не знаю»-ответе,
детерминированно тестируется. Цена — менее «умный» вопрос. Темы — заголовки разделов ближайших чанков (cosine ≥ 0.55; ниже — шум, тем не предлагаем).

## Конвейер и API
`RagAnswer.structured: StructuredAnswer?` (`answer, sources, quotes, verification, idk, idkReason, clarification, relatedTopics, language`).
Поле необязательное, старые конструкторы и потребители работают. `RagPipeline(..., citations = true)` включает контракт для `RagMode.RAG`
(по умолчанию выключено, чтобы Day 22/23 и их оценки не менялись); чат (`ChatRequest.citations`, по умолчанию `true`), `ask` и приложение включают его.
`Without RAG` не имеет источников по определению — UI это прямо пишет. `ask(question, mode, config, history)` не менялся — готово к мини-чату Day 25.

## UI
Веб-чат: ответ; «Sources» (файл > раздел, chunk_id, score); цитаты как blockquote с ✓ (проверена) / ⚠ (не проверена); карточка «Не знаю» с уточняющим вопросом;
«Verification report» в debug. Приложение: под ответом блоки **Sources** и **Quotes**, при «не знаю» — только текст с вопросом.

## Ограничения (честно)
- **Совпадение смысла с цитатами оценивает LLM той же модели** (`QuoteJudge`, температура 0): помечено LLM-judged, склонность к самооценке возможна.
  Все 5 вердиктов PARTIAL — придирки к формулировке вопроса («Day 2», «10–15 минут»), а не к утверждениям ответа; ручная проверка по каждому ответу — «совпадает».
- Проверка — подстрока: она доказывает, что цитата **настоящая**, но не что она **достаточна** для каждого слова ответа. Мелкий вывод модели (c08) ловит только человек/судья.
- 12 вопросов, один автор, один прогон (кэш LLM на диске `rag/cache/llm`, температура 0). c10 зависит от `answerable=false` модели — это не гарантия: при ошибке модели
  сработает только проверка цитат, а выдуманную, но дословно найденную цитату с неверным выводом она не поймает.
- `section` в источнике — первый заголовок чанка (structure-чанк может охватывать несколько подразделов), поэтому подпись иногда не совпадает с темой цитаты.
- Приложение (Interactions API) просит JSON только промптом; на реальном устройстве не проверялось (юнит-тесты на фейках).
- Дополнительная латентность: 1 вызов; до 2–4 при повторах/ремонте JSON.
