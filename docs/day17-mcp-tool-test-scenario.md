# Сценарий проверки инструмента MCP (Day 17)

Ручной сквозной сценарий для проверки, что агент реально вызывает инструмент на собственном
MCP-сервере (Firebase Cloud Function поверх wger.de) и использует результат вызова в ответе.

---

## Подготовка

1. Убедитесь, что в `local.properties` задан рабочий `GEMINI_API_KEY`.
2. Соберите и установите отладочную сборку:
   ```bash
   ./gradlew :app:installDebug
   ```
3. Откройте Logcat (например, без фильтра или с фильтром по тегу приложения) — полезно видеть
   сетевые ошибки, если сервер окажется недоступен.
4. Откройте приложение — попадаете в обычный экран чата.

---

## Шаг 0 — Проверка сервера напрямую (до UI)

Убедитесь, что развёрнутый MCP-сервер отвечает, прежде чем проверять его из приложения:

```bash
curl -s -X POST https://us-central1-ai-challenge-mcp.cloudfunctions.net/mcp \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
```

**Ожидаемый результат:** JSON-RPC ответ со списком двух инструментов — `get_exercise_info` и
`suggest_workout`, у каждого — `inputSchema` с описанием параметров.

---

## Шаг 1 — Выбор агента с инструментами

1. В чате откройте выбор агента/персоны.
2. Выберите **«Fitness Coach (MCP tools)»**.

**Ожидаемый результат:** имя и описание агента в шапке чата меняются на выбранную персону; чат
продолжает работать как обычно (это тот же экран, что и для остальных агентов).

---

## Шаг 2 — Вызов инструмента `get_exercise_info` (happy path)

1. Отправьте сообщение: «Какие мышцы работают при становой тяге?» (или: *"What muscles does a
   deadlift work?"*).

**Ожидаемый результат:**
- Ответ приходит не сразу (уходит на один "лишний" раунд дольше обычного чата) — за это время
  агент: (1) отправил модели список инструментов, (2) получил от неё `function_call` на
  `get_exercise_info`, (3) вызвал реальный MCP-сервер, (4) отправил результат обратно, (5) получил
  финальный текст.
- Финальный ответ содержит конкретные факты о становой тяге (целевые мышцы, категория), которые
  соответствуют данным wger.de, а не только общие знания модели.
- Никакого краша/зависания приложения.

---

## Шаг 3 — Вызов инструмента `suggest_workout`

1. Отправьте сообщение: «Составь план тренировки ног на 20 минут для новичка» (или: *"Suggest a
   20-minute beginner leg workout"*).

**Ожидаемый результат:**
- Ответ — конкретный план из нескольких упражнений с подходами/повторениями, укладывающийся в
  заявленное время, а не общий совет "делай приседания и выпады".

---

## Шаг 4 — Вопрос, не требующий инструмента

1. Отправьте сообщение, не связанное с конкретным упражнением/планом, например: «Как часто нужно
   отдыхать между силовыми тренировками?»

**Ожидаемый результат:**
- Агент отвечает как обычно, без вызова инструмента (ответ приходит с обычной скоростью, без
  дополнительного раунда).

---

## Шаг 5 — MCP-сервер недоступен

1. Временно испортите соединение (например, включите авиарежим) или используйте сборку с заведомо
   неверным `FITNESS_SERVER_URL` (для проверки в тестовой сборке — необязательный шаг для CI, но
   полезно один раз проверить вручную).
2. Отправьте агенту сообщение, требующее инструмента.

**Ожидаемый результат:**
- Приложение показывает понятную ошибку вместо краша (соединение с MCP-сервером не установлено /
  сеть недоступна). Обычный чат (агент «Personal Trainer») продолжает работать, так как не
  использует `McpToolCallingAgent`.

---

## Шаг 6 — Существующий функционал не сломан

1. Переключитесь обратно на агента «Personal Trainer» или «General Assistant».
2. Отправьте обычное сообщение.

**Ожидаемый результат:** чат с Gemini работает как раньше — новый код (`McpToolCallingAgent`,
изменения в `GeminiModels`/`GeminiApiClient`) не влияет на персоны, не использующие инструменты.

---

## Автоматизированная проверка (дополнение к ручной)

```bash
./gradlew :app:testDebugUnitTest --tests "com.example.geminichat.agent.mcp.*"
```

Юнит-тесты `McpToolCallingAgentTest` покрывают то же самое (вызов инструмента и использование
результата, ответ без инструмента, ошибка инструмента, недоступность сервера, кэширование
соединения) без сети/эмулятора — используйте их для быстрой проверки после любых будущих правок.

---

## Итог

| Критерий приёмки | Проверено |
|---|---|
| Агент делает вызов к MCP-инструменту | Шаг 2, Шаг 3 |
| Агент получает и использует результат вызова в ответе | Шаг 2, Шаг 3 |
| Инструмент вызывается только когда нужен | Шаг 4 |
| Ошибки MCP-сервера обрабатываются корректно | Шаг 5 |
| Существующий функционал не сломан | Шаг 6 |
